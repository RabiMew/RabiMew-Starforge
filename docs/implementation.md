# 实施、双语内容与验收

## 1. 当前交付状态

已交付：设计文档、34 个概念配方（SF-01..34）、8 阶段依赖、7 条路线共 34 个任务、8 区域说明（含小行星带）、仓储成长与统一流体经济设计、殖民人口与驻军体系、殖民岗位与维护体系、战斗基准清单、体验辅助与性能层候选记录、自定义物品/提示/GUI/首领提示的中英文内容源，以及静态校验工具。

未交付：模组安装包、运行脚本、真实配方注册、FTB Quests SNBT 导出、ProgressiveStages 配置、生态配置、适配附属或游戏内测试记录。这些需要先锁定并启动具体模组组合；本轮请求是设计，因此保留清晰的数据与执行边界。

`design/content.json` 是整合包自有的设计数据格式，**不是任何 Mod 可直接读取的配置**。`localization/` 是唯一文案源，后续构建时再生成相应资源。不要把设计 JSON 直接放到 `config/incontrol` 或 `config/ftbquests`。

## 2. i18n 规范

逻辑命名统一为 `modpack.<领域>.<对象>[.<字段>]`，全部小写、下划线，固定语义 ID，不把中文、任务序号或版本号写进键。

| 内容 | 例子 |
| --- | --- |
| 阶段名称 / 描述 | `modpack.stage.electric_age` / `modpack.stage.electric_age.description` |
| 任务标题 / 说明 | `modpack.quest.ic2_generator.title` / `modpack.quest.ic2_generator.description` |
| 自定义物品 | `modpack.item.space_control_core` |
| 消息 | `modpack.message.horde_warning` |
| 星球说明 | `modpack.planet.mars.description` |
| GUI | `modpack.gui.base_status` |
| 首领/事件 | `modpack.boss.ruin_guardian.name` / `modpack.boss.ruin_guardian.warning` |
| 教程 | `modpack.tutorial.power_priority` |

`zh_cn.json` 与 `en_us.json` 必须拥有相同键、非空值和相同参数占位符。采用 Minecraft 可翻译组件支持的 `%1$s`、`%2$s` 等索引参数；动态数值先格式化，阶段/星球名称以嵌套可翻译组件传入，不拼接显示文本。屏幕上的单位、按钮、失败原因和物品提示也必须有键。

语言映射只在客户端渲染，服务端发送语言键与参数，不能在服务端预先翻译成中文再广播。`zh_cn` 客户端与 `en_us` 客户端在同一服务器上必须各自得到本地语言。

### 文案准则

中文用“电路、处理器、炮塔、空间站、温室、怪潮”等通用术语；模组名称作专名，普通句子不无必要混入英文。“霜原星”是本包对 Glacio 的暂定统一译名，最终绑定后若原模组已存在自然、稳定的通用译名，统一调整语言值，不改逻辑 ID。提示先说发生什么，再说可以怎么做；不用生硬音译。

错误示意和日志说明属于开发文档，不是玩家文本。任何进入游戏的自定义文案只能从语言源生成。校验器的终端诊断属于开发工具输出，不是 KubeJS 游戏消息。

### 不同消费端的适配

- KubeJS 消息：使用目标版本已验证的可翻译组件构造方式；不得使用硬编码 `.tell("中文")`，也不得把键拼成普通字符串当翻译完成。资源输出目标为 `kubejs/assets/starforge/lang/{locale}.json`。
- 自定义物品：优先显式指定可翻译名称；若原生只能读取 `item.<namespace>.<path>`，由构建器从 `modpack.item.*` 生成原生别名，避免维护两份文案。注册 ID、模型 ID 和语言键分别映射。
- ProgressiveStages：作者当前文档存在 `display_name`/`description` 字符串示例，不能推断它接受语言键或组件。锁定版本实测后选择原生翻译支持；否则禁用其硬编码 toast，使用可翻译通知，并为阶段 GUI 加适配。[作者文档](https://modrinth.com/mod/progressivestages)
- FTB Quests：2101.x 原生支持 `quests/lang/<locale>.snbt` 语言文件，键按确定性对象 ID 索引（`quest.<HEX>.title` 等）。`tools/export-quests.mjs` 从 `design/content.json` + `localization/*.json` 生成章节 SNBT 与双语 lang 文件；结构文件不含任何文案。细节与字段格式见 `docs/questbook.md`。[FTB Quests 官方文档](https://docs.feed-the-beast.com/mod-docs/mods/suite/Quests/Developer/Quests/)
- 第三方缺译：通过资源包的原 Mod 命名空间补语言键，保留原 JAR。不在整合包 `modpack.*` 中冒充可覆盖第三方原有键。

KubeJS 1.21+ 的配方查看器事件与旧版本接口不同，应以 7.2 对应 API 为准；不抄旧版 `JEIEvents` 脚本直接宣称可用。[KubeJS 更新说明](https://kubejs.com/wiki/other/major-updates) / [事件目录](https://kubejs.com/wiki/events)

### JEI / EMI 可见性

全部配方始终完整显示（纯软锁模型下不存在"未解锁配方"）；物品提示可标注其材料层级（tech-tiers.json 的预期时代）作为规划参考。已删除的重复配方隐藏，实验性未实现物品不显示。全阶段图与任务目录始终可阅读。

JEI/EMI 可见性不承担安全或进度正确性——服务端没有任何制造/使用拦截，配方材料链本身就是门槛。EMI 替代配置必须独立测试，不能以 JEI 的结果充当 EMI 通过。

## 3. 任务目录策略

每条路线的 4 个任务使用稳定 ID，`depends_on` 默认空数组，不跨路线强制依赖；`suggested_stage` 只用于显示推荐阶段，不能自动变成任务锁。七条路线全部可见。

任务说明采用“目标—操作提示—为什么值得做”的简短形式。复杂指南通过单独 tutorial 键展示。所有默认任务 `grants_stage=false`、`consumes_items=false`；检测类只观察已有设施或成果，阅读类由玩家确认。

任务类型绑定时区分：物品检测、观察运行、阅读确认、可选手工里程碑。无法自动验证的建筑/运营目标采用说明+确认，不伪造基于方块数量的“运行成功”。`design/content.json` 中不包含假任务类型 ID 或未经验证的自动检测代码。

## 4. 后续目录与责任

```text
design/                      设计数据和后续语义物品映射
localization/                唯一人工维护的中英文文案
tools/                       验证器；后续加入导出工具
docs/                        规则、证据与验收记录
客户端/                      后续生成客户端覆盖文件与安装清单
服务端/                      后续生成服务端覆盖文件与启动说明
```

实施时共同源分别导出 KubeJS startup/server/client scripts、数据包、资源包、FTB Quests 与阶段配置；两个发行目录不各自维护一份业务逻辑。服务端负责阶段、权限、掉落和怪潮，客户端负责语言、教程 UI 与可见性。世界存档中的阶段/基地状态与静态配置分开保存，包含 schema 版本和迁移路径。

脚本引用物品、流体、实体、维度、配方类型必须通过语义映射；映射缺失在构建时失败，不能静默跳过而导致某模组原始配方绕过材料门槛。机器配方若不可数据化，列为 Java 适配项，禁止“运行前没有报错”替代行为验证。

## 5. 实施顺序

| 批次 | 交付 | 验收出口 |
| --- | --- | --- |
| P0 兼容基线 | 30 个内容模组、体验辅助与性能层候选及必要依赖锁定、两端启动、注册表和配方导出 | 单人/专服均加载，核心机器没有缺失映射 |
| P1 工业闭环 | T0–T3、IC2/BC/IE/AE2 关键配方、地球资源 | 从新世界做到首次 ME 自动合成；无模板/能源冷启动循环 |
| P2 防御原型 | T2 塔与弹药、固定波次、拆搭白名单 | 能补弹、友军安全、可恢复且性能可测 |
| P3 重工与原子 | T4–T5、核电与 UU 初样、T7 地球配方 | 不进太空、不打 Boss 可制造量子组件 |
| P4 航天联动 | 火箭各级、氧气、站点、全部航天材料地球途径 | 首次发射依赖工业；所有航线无循环材料门槛 |
| P5 殖民生态 | 七区域池、基地威胁、空间站事件、自动远端补给 | 多基地无叠加袭击，空间站默认零敌对 |

每一批新增文案同步维护两种语言，不推迟到 P6 才翻译。P6 是全量复核。所有阶段都有可独立试玩的出口，不以未完成的外星内容拖住地球工业。

## 7. 核心验收场景

1. **地球 T7**：固定种子新生存档，不进入外星、不击杀 Boss、不领取任务奖励。验证首份铱、UU 样本、全部处理器、量子组件及装备可达；成本不得超过既定地球/外星比值。
2. **首航冷启动**：所有发射台、燃料、氧气、航天材料和控制组件均在发射前可从地球生产。逐级检查火箭的发动机、燃料箱、机体材料、制造台和目的地限制。
3. **软锁抽查**：手工/配方书/原版合成器、BC、IE、IC2、AE2 自动合成、战利品、交易、拆机、升级组件一律可用（无阶段拦截）；廉价捷径不得替代时代材料链——禁用发电机无配方、村民交易不提供科技件、里程碑奖池不给深空材料；凭证物品必须由亲手制造，拾取或购买不授予里程碑。
4. **多人状态**：两个不同进度团队；新人加入、队长退出、合并/解散、服务器重启、玩家离线。机器拥有者稳定；公共机器显式分配归属，不继承最后点击者的高阶段。
5. **能源与材料守恒**：循环充放电、EU/mEU/FE/MJ/AE 桥、桶装流体、统一石油链中 BC 与 IP 流体互认、精炼/回收、施工工具撤销；不能复制物品、流体、库存或能量。
6. **补给与故障**：炮塔耗尽、缓冲箱满、AE2 断电、量子桥一端卸载、火箭燃料不足。显示明确提示；恢复后不中断库存守恒，不无限重发物资。
7. **敌对生态**：逐维度核对自然池、遗迹/事件池、温度与氧气伤害、瞬移和搭桥边界。火星有可见群体战术，霜原重型单位有可读攻击动作。
8. **安全空间站**：测试自然刷怪、刷怪笼、怪潮、模组事件、跨维度转移、登录重载；正常模式 0 个未经授权敌对。特殊事件最多 4 个且仅在允许区域，过期豁免不能复用。
9. **攻城不毁档**：工程兵全预算用尽、离线、临时桥清理、建筑工具修改桥块、多人领地相邻；不误删玩家方块、不回滚正常库存、不破坏受保护设备。
10. **厨房与温室**：两套厨房配方、碗/燃料回流、库存优先级、温室失压、停电与恢复、伪装方块气密。记录哪些自动步骤确实支持。
11. **语言**：两个客户端同时选择 zh_cn/en_us；切换语言、重连、阶段弹窗、Boss 栏、任务、工具提示均无裸键、混杂语言或参数错位。
12. **性能与恢复**：按防御文档基准测试 1/4/8 人、2 处攻城、后台工业与区块加载；降级后不补发积压怪潮。保存并恢复基地状态与事件预算，崩溃恢复不能重复发奖励。
13. **殖民驻军**：第一批居民地球招募与火箭运输；守卫武装、弹药取用与低血量找食物；未加载殖民地摘要状态；NPC 航天服环境保护生效性；三层防御分工不互相取代；战斗基准 TTK 双向达标；完全 AFK 不是最优解。
14. **岗位与维护**：无人基地以 100% 基础能力运转，岗位不是工业前置；同产线岗位增益边际递减生效；岗位绑定基地 UUID 不跨星球；未加载基地不跑完整 AI；维护只给正奖励、无随机损坏惩罚；换岗与 Easy Villagers 打包/放回后岗位数据正确。

静态校验覆盖：语言键一一对应、内容引用存在、参数一致、阶段 DAG 无环、T7 不依赖 T6、晋级凭证的材料层级属于前置时代集合（tech-tiers.json 一致性）、任务不授予阶段和不消费物品。它不分析实际 Minecraft 配方图，也不替代以上运行场景。
