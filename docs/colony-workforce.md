# 殖民岗位与维护

本文件是设计行为规范，集中描述村民 × 工业 × 后勤 × 维护 × 专业岗位体系；岗位效果、工作站与增益均为设计目标，未经游戏内实测。

## 1. 核心原则

机器决定科技能力，能源决定机器能否运行，物流决定生产能否持续，**村民决定殖民工业运行得是否更高效、更稳定、更专业**。

- 无人生产 = 100% 基础能力，基础机器始终能无人运行。
- 有合适岗位 = 有限效率提升。
- 完整岗位 + 维护 + 物流 = 最佳状态。

村民放大工业能力，而不是创造工业能力；村民不是机器启动条件，也不是每台机器绑定一个村民。纯自动化玩家仍可发展完整科技树；经营殖民地的玩家获得更高效率、更低维护成本、更稳定后勤、更好的预警与更专业的产线。

## 2. 不做真实逐机器 AI

岗位村民**不**在机器之间来回走动，不逐 tick 搜索机器/库存/能源/待修设备，不真实搬运物品——那会制造寻路、碰撞、区块扫描和 AI 调度开销。

采用**工作站抽象**：村民 → 分配到工业工作站 → 工作站注册到所属基地（基地 UUID/区域）→ 低频读取基地摘要 → 提供对应增益。工作站统计频率为数秒至数十秒级，具体周期实测确定；岗位 NPC 工作时间只在工作站附近 8–16 格活动，不跨 256 格基地自由寻路。若无法可靠限制，宁让岗位 NPC 大部分时间停留在工作站附近。

岗位效果只作用于所属殖民基地：主世界的一名机械师不能让全服所有星球工厂获得增益，远端基地需要自己的岗位人员——殖民扩张因此需要人口与后勤。未加载基地不运行村民 AI，仅保存岗位分配、维护状态、库存目标与基地摘要，不离线无限生产。

## 3. 岗位 × 科技阶段 × 作用 × 实现方式

| 岗位 | 阶段 | 对应系统 | 作用（设计目标） | 实现方式 |
| --- | --- | --- | --- | --- |
| 农业工 | T0 | Easy Villagers / Farmer's Delight / 温室 | 提高农业设施效率、稳定食物产出、降低部分农业维护消耗、农业库存提示 | 工作站摘要增益；不凭空生成食物 |
| 厨房/后勤工 | T0 | Farmer's Delight / 懒人厨房 / 食堂 | 提高食物加工效率、管理食物安全库存、低食物预警、优先保障守卫居民供餐 | 基地库存摘要；不逐个送餐 |
| 仓库管理员 | T0 基础 / T1 正式 | Storage Drawers / Sophisticated Storage / BC / AE2 | 最低库存目标、缺货提示、前线需求统计、本地缓冲与补给优先级 | 决策与优先级层；不替代 AE2，搬运仍由原物流执行 |
| 机械师 | T1 | IE / BC / 通用机械产线 | 小幅提高机械效率、降低维护需求与停机惩罚、机器维护状态 | 基地级有限增益 |
| 电气技师 | T2 | IC2CRE 电网 / 储能 / 电气设备 | 小幅降低部分能耗、电网状态提示、低电力预警、维护效率 | 不改变真实电压与 EU/mEU/FE/MJ 换算，不绕过 IC2 电压规则 |
| 军械师 | T2 | TaCZ / IE 武器 / 弹药 / Guard Villagers | 枪械弹药生产增益、弹药库存管理、守卫补给提示、武器维修与特殊弹药工序候选 | 军工链增益；不给守卫无限弹药 |
| 网络操作员 | T3 | AE2 / 自动合成 / 调度 | 更完善库存预警、生产请求调度、远端补货逻辑、减少缺货与过量生产 | 不把 AE2 原始传输速度提高到违反模组机制 |
| 重工业技师 | T4 | IE 大型机器 / BC 采石场 / 重工业 | 提高大型设备吞吐、改善维护、降低维护材料消耗 | 高级岗位/专精替代，不与机械师指数叠加 |
| 高级岗位（高级电气技师、控制室技术员、高级军械师、高级物流管理员等） | T3–T5 进阶 | 对应系统 | 原岗位升级版本，非额外叠加 | 原村民 + 升级工作站 + 科技解锁，不要求重新刷特殊村民 |
| 生命保障技师 | T6 | Ad Astra 氧气/水/居住区 | 氧气库存预警、应急供氧优先级、生命保障维护、居住区状态 | 不凭空制造氧气 |
| 航天机械师 | T6 | Ad Astra 火箭/发射设施/外星基地维护 | 航天设备维护、火箭准备效率、殖民设备维护、发射前检查 | 不把火箭燃料消耗降到破坏航天经济 |
| 高级工程师 / 量子设备技师 | T7 候选 | 量子工业 | 少量精英增益 | 禁止“一个量子工程师 = 全机器翻倍”式膨胀 |

## 4. 增益克制与边际递减

首轮目标：单个合适岗位约 +5%～10% 吞吐，或约 −5%～10% 能耗/维护成本；不同时叠加 +20% 速度 −20% 能耗 +20% 产量。同一产线人力收益边际递减：第一名技师 100% 岗位效果，第二名 50%，第三名 25%，之后无额外收益；或每个岗位/区域只接受一个主要负责人。避免在机器旁塞 40 个村民刷效率。

若第三方机器无法安全改变速度，**不强行 Hack**：岗位收益可转化为减少维护消耗、增加副产物概率、改善批量配方成本、提供生产计划提示、减少输入浪费、改善库存管理。实现优先级：现成 Mod API/配置 → KubeJS/数据包安全部分 → Starforge 小型适配层 → 最后才考虑复杂核心修改；不为 +5% 效率 Mixin 整个 IC2/IE 机器系统。

## 5. 工作站与人口分配

岗位系统如需自行实现，优先少量通用工作站：工业控制台、军械工作台、后勤控制台、生命保障控制台；避免每种职业一个复杂方块。工作站负责分配村民、显示岗位与基地状态、低频读取基地摘要、提供对应效果，不逐 tick 扫描基地。

殖民人口产生取舍：10 人殖民地可以是 2 农业 + 2 工业 + 1 后勤 + 2 守卫 + 3 普通居民，也可以是 4 工业 + 1 农业 + 1 后勤 + 4 守卫——不同分配不同优势，没有唯一正确答案。允许普通居民、儿童与无岗位人口存在。Guard Villager 是军事岗位，不兼任机械师或仓库管理员；支持换岗时须先退出原岗位再重新分配。高级岗位通过原村民 + 升级工作站 + 科技解锁获得，不要求重新找“更高级村民”。

视觉上让基地看起来有人工作：鼓励建设控制室、工程办公室、仓库值班室、军械库、食堂、生命保障中心，工作站放置其中，村民只在有限范围活动。

## 6. 维护系统

沿用 `colony_maintenance`（殖民维护组件）作为切入点，采用**正向维护奖励**而非随机损坏惩罚：

- 机器正常运行：100% 基础能力。
- 维护良好：少量效率提升、少量能耗优化、减少生产停顿、延长部分装备/设施维护周期。
- 没有维护：仍然正常工作。不搞机器随机爆炸、永久损坏、“NPC 没上班就停产”。

维护消耗已有工业材料：殖民维护组件、钢件、橡胶、润滑材料、电气组件；不引入齿轮油/轴承油/各级维修螺丝式物品膨胀。

## 7. 物流管理员与物资优先级

“人类管理”体现在决策与优先级，不在实体搬运。物流管理员维护最低库存目标（示例：食物 < 256 → 补货；步枪弹药 < 512 → 补货；炮塔弹药 < 2 场怪潮需求 → 补货；氧气 < 30% → 紧急；应急电池 < 25% → 紧急），实际运输仍由 AE2 / BuildCraft / 已有库存系统执行。沿用既有优先级：应急氧气 > 应急供电 > 基地防御 > 食物 > 关键生产 > 普通工业 > 非必要生产；有管理员时优先级更容易自动执行或提示，没有时玩家仍可手动管理。

## 8. 与威胁值 H 的关系

沿用既有规则：村民数量与岗位本身不直接提高 H（不做“每个工人 +X”），否则最优解会变成全自动无人基地。岗位提高产量后，实际生产活动上升 → P/M/C 自然提高 → H 自然上升，间接路径已经足够。

## 9. 状态展示

基地状态界面增加人口、工人、守卫、空闲居民、岗位分布、维护状态、食物库存、弹药库存、氧气与电力状态——目标是“一眼知道这个殖民地缺什么”，不做复杂城市管理界面。状态用语义等级：良好 / 注意 / 紧缺 / 危险，不堆几十个无意义百分比。

## 10. 待游戏内验证

- Guard Villagers：能否安全分配/取消工业岗位、换岗后数据是否正确、是否错误保留战斗 AI。
- Easy Villagers：打包/放回后岗位是否保留、NBT 是否安全、多人是否正确。
- 第三方工业模组：是否允许安全增加效率、是否有公开 API、还是只能通过配方间接实现。
- 工作站摘要更新周期的实测开销；巡逻/岗位 AI 的 MSPT。

不能确认的项全部标记“待游戏内验证”，不编造第三方 API 与实测数据。
